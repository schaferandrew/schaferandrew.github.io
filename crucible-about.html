About Crucible

Under construction. Crucible is a work in progress: tests, scoring and results are still changing, and some numbers here come from early or partial runs. Check back soon.

This page was created and written by or with the help of AI.

Crucible is a small benchmark harness for testing models on the work people actually hand them: building and fixing code, editing writing, answering everyday questions, reasoning through a schedule, diagnosing a leak. The aim is to answer a practical question: which model, through which tool, on which hardware, is good enough for this job?

How a run works

  1. Test. Each test is a YAML file: the prompt, a rubric of weighted criteria, and anything it needs, such as a seeded repo, fixture files or a mock email-and-calendar server.
  2. Harness. The harness hands the prompt to the model. Chat tests always use direct, a single API call with no tools. Agentic tests use a coding agent, opencode or pi, that can read and write files, run commands and browse. The same model can do very differently depending on the agent, which is why the Agentic results let you switch between them.
  3. Model. Local models run through LM Studio or Ollama; cloud models run through OpenRouter as a reference point.
  4. Run folder. Every run writes a folder with the prompt, the full transcript, the files the model produced, and the metrics: time, time to first token, tool calls, tokens and cost.
  5. Score. Each run is scored 0–10 against its rubric, by a person or by an AI judge (an agent score). Some tests have a critical failure, like wrong interest math or an invented news story, that caps the score.
  6. Export. Scored runs are flattened into one JSON file that drives the results page.

Sections and areas

Every test is either Chat or Agentic, and the two are never mixed: not in a run, not in a score. Within each, a test's area is the kind of work it covers, and every test ID is its area's four letters and a number (CODE-11, WRIT-2b).

AreaWhat it meansExamples
Chat · one API call, no tools
Writing WRIT Can it edit without flattening someone's voice, and write things that sound real? Proofread an email, a literary paragraph and an economics essay; generate believable character names; a haiku with banned words.
Math & logic MATH Does it get the exact answer, including when the obvious one is wrong? Recipe scaling and discounts, compound interest and a split bill, competition-style counting and probability, a logic puzzle.
Geography GEOG Does it know the world beyond the obvious answer? Capitals that aren't the biggest city, which countries are landlocked, trick questions about borders and time zones.
History HIST Are its dates and order right, and can it catch what's wrong? Put events in order, fact-check a paragraph, spot the anachronisms in a letter from 1863.
General knowledge KNOW Does it know things, explain them clearly, and stay faithful to what it's given? Explain enshittification or solar panels, fix a leak or a running toilet, write a news briefing from supplied feeds without changing a figure.
Agentic · an agent harness with tools and a workspace
Coding CODE Can it do software work in a real repo, with real tools? Build an interest-rate CLI, make a navbar responsive, fix a Next.js server/client bug, fix a redirect loop and an accessibility audit in a monorepo.
Research RSCH Can it go and get live information, and report it honestly? Today's local news, the weather against the historical average.
Everyday TASK Can it handle the tasks you'd hand an assistant, using your own data? Find meeting times across two calendars, a morning brief from email, calendar and news.

Tiers

Tests are also sorted by how hard they are, so a small model isn't judged on work meant for a frontier one.

  • Spark: the basics. Does it load, follow a format, call a tool, read code and make a small correct change? This is a gate: a model that fails Spark isn't ranked.
  • Temper: real everyday work you'd actually use. This is the headline score.
  • Forge: long, multi-step work you'd normally need a frontier model for.

Every area is working toward tests at all three tiers; math, geography and history already have one of each.

Programmatic checks

Writing, math, geography and history tests are scored with no judge at all: each rule below runs on the model's final answer, passes or fails, and is worth a fixed number of points. Anyone running the same answer through Crucible gets the same score. The answer that was checked is saved with the result, so every score can be audited later. Tests that need judgment (does the code actually work, is the advice safe) use an AI judge instead, with deterministic checks wherever a rule can be stated exactly.

Keeping scores comparable

Every test is versioned. If a prompt or its files change, old runs of it stop counting until they're rerun; if only the rubric changes, the saved outputs are re-scored. Published scores are always on a release, a pinned list of tests and versions, so adding a test never quietly moves anyone's score. New tests start provisional and only count once they've been checked against small, mid-size and frontier models to confirm their tier.

Run it yourself

Crucible is open source. You need Python 3.9+, Node.js for the agent harnesses (opencode or pi) and, for local models, LM Studio or Ollama; cloud models run through OpenRouter.

git clone https://github.com/schaferandrew/crucible.git
cd crucible
uv sync
uv run crucible run

crucible run asks which model, what to run (everything, Chat, Agentic, an area, a tier or single tests) and, for agentic tests, which harness, then prints the one-line command to repeat it. Without uv: python3 -m venv .venv, activate it, pip install -e ..

schaferandrew/crucible on GitHub has the full setup for each harness and provider.
