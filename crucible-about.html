About Crucible

This page was created and written by or with the help of AI.

Crucible is a small benchmark harness for testing models on the work people actually hand them: building and fixing code, editing writing, answering everyday questions, reasoning through a schedule, diagnosing a leak. The aim is to answer a practical question: which model, through which tool, on which hardware, is good enough for this job?

How a run works

  1. Task. Each task is a YAML file: the prompt, the checks or hidden tests that score it, and anything it needs, such as a seeded repo, fixture files or a mock email-and-calendar server.
  2. Harness. The harness hands the prompt to the model. Chat tasks always use direct, a single API call with no tools. Agentic tasks use a coding agent, opencode or pi, that can read and write files, run commands and browse. The same model can do very differently depending on the agent, which is why the Agentic results let you switch between them.
  3. Model. Local models run through LM Studio or Ollama; cloud models run through OpenRouter as a reference point.
  4. Run folder. Every run writes a folder with the prompt, the full transcript, the files the model produced, and the metrics: time, time to first token, tool calls, tokens and cost.
  5. Score. Each run is scored 0–10 automatically: chat answers by fixed checks, agentic work by hidden tests the agent never sees, run on the repo it left behind. Some tasks have a critical failure, like wrong interest math or an invented news story, that caps the score. Repeat runs of the same setup are averaged.
  6. Publish. Each run, score and status record is published as its own file, keyed by the run's permanent ID, and never edited afterwards: a rescore adds a score record, and a bad run gets a status record marking it invalid. The results page joins them for the suite you pick.

How scores are made

Every score is computed automatically, the same way every time. Chat tasks are scored by fixed rules that run on the model's answer: each passes or fails and is worth a fixed number of points. Agentic tasks are scored by hidden tests, a test suite the agent never sees, run against the repo it leaves behind. Anyone running the same answer through Crucible gets the same score, and the answer that was checked is published with the result, so every score can be audited. Versions: Crucible and the suite

Two version numbers matter here. Crucible{% if cr_latest.crucible_version %} ({{ cr_latest.crucible_version }} published this suite's catalog){% endif %} is the tool you install: the command line, the harnesses, the scoring engine and the format results are published in. The suite ("Suite {{ cr_latest.suite.id | default: "v1" }}") is which tasks are scored, at which version, with which tiers and weights. The leaderboard always names the suite it shows, and the selector at the top of the results switches to an earlier one.

  • A suite cut (Suite v2 → v3) promotes new tasks, retires old ones, or changes tiers and weights. Each suite is frozen once cut, so a score in Suite v2 means the same thing forever.
  • A suite patch (v3 → v3.1) only fixes how a task is scored. Saved answers are rescored; nothing needs rerunning.
  • Runs belong to every suite that includes their task unchanged. If a task's prompt or files change, it gets a new version and older runs of it stop counting until they're rerun. A run from October still counts in a later suite if its task didn't change.
  • New tasks start provisional: they run, but appear here only once a cut makes them active, after they've been checked against a small, a mid-size and a frontier model.

The full rules are in Crucible's versioning doc, and what changed in each suite is in its changelog.

Run it yourself

Crucible is open source. You need Python 3.9+, Node.js for the agent harnesses (opencode or pi) and, for local models, LM Studio or Ollama; cloud models run through OpenRouter.

git clone https://github.com/schaferandrew/crucible.git
cd crucible
uv sync
uv run crucible run

crucible run asks which model, what to run (everything, Chat, Agentic, an area, a tier or single tasks) and, for agentic tasks, which harness, then prints the one-line command to repeat it. Without uv: python3 -m venv .venv, activate it, pip install -e ..

schaferandrew/crucible on GitHub has the full setup for each harness and provider.
