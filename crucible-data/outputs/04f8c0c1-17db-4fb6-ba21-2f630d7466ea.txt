TypeScript compiles cleanly. Here's a summary of the work.

## Diagnosis

`app/page.tsx` was written as a **client-style component inside an App Router Server Component**:

- It had no `"use client"` directive, so Next.js treats `page.tsx` as a **Server Component** — yet it called React hooks (`useState`, `useEffect`). Hooks can't run during server rendering.
- The data fetch used a **relative URL** (`fetch('/api/account?id=acct_1')`) from the client. Relative URLs have no origin, so `fetch` throws `Invalid URL` and never resolves — leaving the page permanently stuck on "Loading...". I reproduced this exact failure before fixing.

## Fix (idiomatic modern Next.js)

Converted the page into an **async Server Component** that awaits data directly — the canonical App Router pattern for the server data-access boundary:

```tsx
async function getAccount(id: string) {
  const res = await fetch(`/api/account?id=${id}`, { cache: 'no-store' });
  if (!res.ok) return null;
  return res.json();
}

export default async function AccountPage() {
  const account = await getAccount('acct_1');
  if (!account) return <p>Account not found</p>;
  return ( ... Name/Plan ... );
}
```

This preserves the existing structure and intent (same "not found" fallback, same rendered output) while removing the invalid hooks and client round-trip. The API route stays as the data-access boundary; it's just called server-side via `await fetch` instead of from browser `fetch`.
