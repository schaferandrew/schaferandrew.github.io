### Key Design Decisions

1. **Privacy-first by default**: Public `/api/articles` and `/api/articles/feed` only return `status: "published"` articles. Draft and in-review articles are invisible to the public (matching "the public must never see work that hasn't been approved").

2. **Default publish immediately**: Articles without `status` specified are published immediately, as before — existing RealWorld clients see no change.

3. **Editors configured by username**: `EDITORS=ada,grace` in the env var, or `createApp(db, { editors: ["ada"] })`. The DB stores a `Set<string>` of editor usernames.

4. **Self-approval forbidden**: Both `approve` and `reject` reject 403 if the editor's user ID matches the article author.

5. **No breaking changes to existing contract**: `realworld.contract.test.ts` is unmodified and green. The only new JSON fields on `Article` are `status` and `reviewComment` — extra fields are allowed by the RealWorld spec.

### Items to Flag in Code Review

1. **`editors` on DB vs app config**: Currently `db.editors` is set server-side. Tests use `withEditors(ctx, [...])`. For production clarity, consider passing editors through `createApp` config and having it copy into the DB, rather than mutating the DB directly in `server.ts`.

2. **No pagination on `/api/articles/review-queue`**: The brief doesn't specify pagination for the review queue, but for large review queues this could become slow. Adding `limit`/`offset` support would be a good follow-up.

3. **Review comment trim**: The `rejectArticleSchema` allows empty/whitespace-only comments via `optional()` — a separate `min(1)` on `comment` could prevent truly blank feedback, though the route currently falls back to `null` for missing review objects.
