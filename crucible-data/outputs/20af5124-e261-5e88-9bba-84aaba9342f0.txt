# Lesson 1 — Where Your Code Runs

## The concept

In the App Router, every component is one of two kinds:

- **Server Component (default)** — renders on the server only. Supports `async/await`, can hit the DB directly, can import secrets. Ships *zero* JS. No hooks, no `window`, no event handlers.
- **Client Component** — marked with `"use client"`. Runs on the server *and* the client; ships JS; uses `useState`, `useEffect`, handlers.

`"use client"` is a **boundary marker**, not a file toggle: that file and everything it imports become client components. Boundaries should sit as *deep* in the tree as possible — that's the core performance discipline in Next.js.

**App Router files:** `app/` is your route tree. `page.tsx` renders a route; `layout.tsx` wraps it and *stays mounted across navigations* (why client state in layouts survives route changes).

## Small example

```tsx
// app/teams/page.tsx — Server Component (default)
import { TeamFilter } from "./team-filter";
import { getTeams } from "@/lib/db";

export default async function TeamsPage() {
  const teams = await getTeams();      // runs only on the server
  return (
    <main>
      <h1>Teams</h1>
      <TeamFilter initial={teams} />
    </main>
  );
}
```

```tsx
// app/teams/team-filter.tsx
"use client"; // boundary — everything from here down also runs in the browser

import { useMemo, useState } from "react";

export function TeamFilter({ initial }: { initial: Team[] }) {
  const [q, setQ] = useState("");
  const teams = useMemo(
    () => initial.filter(t => t.name.toLowerCase().includes(q.toLowerCase())),
    [initial, q],
  );
  return (
    <>
      <input value={q} onChange={e => setQ(e.target.value)} placeholder="Filter…" />
      <ul>{teams.map(t => <li key={t.id}>{t.name}</li>)}</ul>
    </>
  );
}
```

**Trace the request:**
1. Request arrives → Next renders `TeamsPage` on the server. `getTeams()` executes; HTML with the full list is streamed to the browser. First paint contains data, with no page JS.
2. Browser downloads the `TeamFilter` bundle, hydrates it, seeds it with `initial`. Typing filters client-side, no network round-trips.
3. The DB call and the `<h1>` never ship as JS.

## Common mistakes (this lesson)

- `"use client"` on `page.tsx` "just in case" — you lose server data access and streaming, and ship more JS.
- Using `useState`/`window` in a Server Component (build error: *"needs useState but is a Server Component"*).
- Passing a **function** prop from server to client — props crossing the boundary must be serializable. (Fix: Server Actions, Lesson 4.)
