The benchmark task is complete. I have diagnosed and fixed the intermittent blank dashboard state issue by addressing a race condition related to session timeouts.

Here is a summary of the actions taken:

1.  **Diagnosis:** The blank state was caused by the client-side dashboard loading shortly after login, which raced against the server's 30-second inactivity timeout (`SESSION_TTL_MS`). If subsequent activity was delayed, the session could expire before the frontend rendered completely.
2.  **Fix Implemented (`server.js`):** I modified the `getDashboardData` function to refresh the session's `expiresAt` timestamp upon successful access. This ensures that any activity, including the initial dashboard load after login, keeps the session alive until truly inactive.
3.  **Regression Test Added (`server.test.js`):** A new `Session Management` suite was added to `server.test.js`. This test rigorously simulates the login flow, waits for most of the 30-second TTL duration (testing the boundary condition), and verifies that subsequent access is successful due to the activity refresh, while still ensuring eventual timeout behavior remains correct.

The application code is now stable against this intermittent blank state issue.
