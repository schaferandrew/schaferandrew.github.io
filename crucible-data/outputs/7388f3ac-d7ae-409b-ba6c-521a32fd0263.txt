## Summary of Findings

### 1. Keyboard navigation for menus and modals
- **What you changed**: Added `tabIndex="0"` to menu items and modal headers, and ensured the `Escape` key closes modals. Implemented `useFocusTrap` from a shared hook to manage focus within dialogs.
- **What you couldn't verify**: Without a real screen reader, we can't confirm if focus is trapped correctly or if focus moves to the first/last item in lists.

### 2. Live region for dynamic content
- **What you changed**: Added `aria-live="polite"` to containers that receive async updates (e.g., search results). Wrote a small observable class to dispatch messages.
- **What you couldn't verify**: The screen reader correctly announces the count of items after a search; we rely on the live region to trigger announcements.

### 3. Form labels and error messages
- **What you changed**: Wrapped each `<input>` in a `<label>` with `htmlFor={id}`. Used zod to validate and populate error messages in the server-rendered form.
- **What you couldn't verify**: A screen reader correctly reads the error text when a field is invalid; we rely on the client-side validation state.

### 4. Skip link to main content
- **What you changed**: Added a `<div role="main">` wrapper around the main content and an `<a href="#main" class="skip-link">Skip to main content</a>` at the top of the body.
- **What you couldn't verify**: The skip link works with keyboard navigation and screen readers; we rely on the semantic wrapper.

### 5. ARIA roles for custom widgets
- **What you changed**: For the custom date picker, added `role="button"` and `aria-pressed`, and handled arrow keys to change the value.
- **What you couldn't verify**: The screen reader correctly announces the pressed state and allows arrow-key navigation.

### 6. Focus management on route changes
- **What you changed**: Used `useEffect` to focus the search input after a 300 ms debounce on route change.
- **What you couldn't verify**: Focus moves to the input immediately after the URL changes; we rely on the debounce to avoid jitter.

### 7. Semantic HTML for tables
- **What you changed**: Replaced `<div class="table">` with `<table>` and added `<thead>`, `<tbody>`, `<tr>`, `<th scope="row">` where possible.
- **What you couldn't verify**: Screen readers announce table headers correctly; we rely on the semantic markup.

### 8. Hidden content for screen readers
- **What you changed**: Added `<div class="visually-hidden" aria-hidden="true">` around hero images so they are ignored by assistive technology.
- **What you couldn't verify**: The screen reader ignores the content as intended; we rely on the class name.

### 9. Form validation messages
- **What you changed**: Integrated zod validation errors into the form state and displayed them under each field.
- **What you couldn't verify**: The screen reader reads the validation message in context with the field name.

### 10. Responsive layout
- **What you changed**: Added `@media (max-width: 768px) { ... }` to reduce padding on mobile and stack list items vertically.
- **What you couldn't verify**: The responsive behavior is correct; we rely on the CSS.

> **Note:** All changes respect the constraints (same component names, props, native elements) and avoid creating new findings. Each fix was verified against the constraints where possible; for any item we couldn't test with a real screen reader, we relied on the expected behavior from the implemented patterns.
