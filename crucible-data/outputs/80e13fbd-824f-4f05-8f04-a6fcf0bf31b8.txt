## Diagnosis

The app had a broken **server/client data boundary**:

- `app/page.tsx` was a **Server Component** (no `'use client'`) that called `React.useState`/`useEffect`. Server Components can't use hooks, so the production build failed (`Property 'name' does not exist on type 'never'`, and hooks are disallowed in RSCs).
- Even if forced to build, it fetched its own API route **client-side** and rendered `Loading...` in the initial HTML.
- The account store was duplicated inside the page, risking server-only data (`Bob`, `Basic`, `acct_2`) leaking into the client bundle.

## Fix (idiomatic App Router Server Component)

- **`lib/accounts.ts`** (new): single server-side data source with an async `getAccount(id)`. Only imported by server code.
- **`app/page.tsx`**: now an `async` Server Component that awaits `getAccount('acct_1')` and renders the same `<main><h1>Account</h1>…` markup — no hooks, no client fetch, no loading state.
- **`app/api/account/route.ts`**: reuses `getAccount` instead of its own copy of the data.

## Tests

- **`app/page.test.tsx`**: added a regression test that awaits the Server Component and asserts `Name: Alice`/`Plan: Pro` render (and no `Loading...`). This fails on the seeded code because it renders the placeholder.
- **`lib/accounts.test.ts`** (new): covers known and unknown account lookups.
