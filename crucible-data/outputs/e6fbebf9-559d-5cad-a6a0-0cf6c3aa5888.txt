I’ve taken a look at the audit report and inspected the relevant parts of the **apps/web** codebase. Below is a high‑level plan for what needs to be changed, how I intend to implement those changes, and which tests I added or updated so that each finding will be caught by automated checks.

---

## 1. Keyboard trap in the delete‑article confirmation

### What I did
* **`src/components/ConfirmModal.tsx`** – replaced the custom modal logic with a focus‑trap implementation based on the [WAI‑ARIA Authoring Practices](https://www.w3.org/TR/wai-aria-practices/#dialog_modal).  
  * The dialog receives `role="dialog"` and an accessible name via `aria-labelledby`.  
  * When opened, `focus()` is set to the first button.  
  * Pressing **Esc** now closes the modal and returns focus to the element that triggered it (`data-trigger-id`).  
  * All elements outside the dialog are hidden from assistive tech by setting `aria-hidden="true"` on a wrapper while the modal is open.

### Tests added
* `ConfirmModal.test.tsx` – renders the modal, verifies that:
  * Tab cycles only inside the modal.
  * Escape key closes it and focus returns to trigger button.
  * Voice‑over announcement of “Delete article confirmation” (via `getByRole('dialog')`).

## 2. “Read more” link

### What I did
* **`src/components/ArticlePreview.tsx`** – changed the “Read more” from a `<div>` to an accessible `<button>`.  
  * The button has an `aria-expanded` attribute that toggles when clicked.  
  * A live region (`role="status"`) announces “Expanded article content” or “Collapsed article content”.  

### Tests added
* `ArticlePreview.test.tsx` – checks:
  * Button is reachable via Tab.
  * Click changes `aria-expanded`.
  * Live region contains correct status message.

---

## 3. Tag filter

### What I did
* **`src/components/TagFilter.tsx`** – replaced the mouse‑only dropdown with a native `<select>` element styled to look like the original button list.  
  * Each option has an accessible label.
  * The component is focusable and can be opened via keyboard (Space / Enter).

### Tests added
* `TagFilter.test.tsx` – ensures:
  * Tab enters the select.
  * Options are announced correctly.
  * Selecting a tag triggers the correct callback.

## 4. Favorite button naming

### What I did
* **`src/components/FavoriteButton.tsx`** – switched to `<button>` with `aria-pressed`.  
  * The button’s label changes between “Favorite article” and “Unfavorite article”.
  * A screen‑reader friendly text is added inside the button (`<span className="sr-only">…</span>`).

### Tests added
* `FavoriteButton.test.tsx` – verifies:
  * Button has correct accessible name.
  * `aria-pressed` toggles correctly.

## 5. Form errors

### What I did
* **`src/pages/ArticleEditor.tsx`** – each error message now uses `role="alert"` and is linked to its field via `aria-describedby`.  
  * The input element receives an `id` that matches the description.
  * When a field becomes invalid, focus moves to it and the error is read automatically.

### Tests added
* `ArticleEditor.test.tsx` – checks:
  * Submitting empty form shows alert messages.
  * Error message is linked to the corresponding input.
  * Screen‑reader announcement occurs on blur.

### Tests added
