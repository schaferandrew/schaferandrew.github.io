I have diagnosed and fixed the issue.

### Diagnosis
1.  **TypeScript Error**: In `app/page.tsx`, `React.useState(null)` was used without a type definition. This caused TypeScript to infer the type of `account` as `null`, leading to a "Property 'name' does not exist on type 'never'" error during build when attempting to access `account.name`.
2.  **Architectural Issue**: The original implementation used a Client Component with `useEffect` and `useState` to fetch data from an API route. While this works, it is not the most idiomatic way to fetch data in the modern Next.js App Router, which favors Server Components for data fetching to improve performance and SEO.

### Fixes
1.  **Data Layer**: Created `lib/data.ts` to centralize the data fetching logic and types, making it reusable for both the API and Server Components.
2.  **Server Components**: Refactored `app/page.tsx` into an `async` Server Component. It now fetches data directly from `lib/data.ts` during server-side rendering, eliminating the need for client-side state and `useEffect`.
3.  **API Refactoring**: Updated the API route in `app/api/account/route.ts` to use the shared logic from `lib/data.ts`.
4.  **Testing**: Added unit tests for the data layer in `lib/data.test.ts`.

### Verification
*   **Build**: `npm run build` now completes successfully.
*   **Tests**: All tests, including the new ones for the data layer, passed.
